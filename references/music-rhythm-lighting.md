# 音乐律动灯效玩法（2026-09-05 实测）

用户兴趣方向：灯光跟随音乐节奏律动。核心原则：**律动感来自时长对比与多灯对位，不是均匀开关**。

## 灯效能力分类（已实测）

| 设备 | 区域 | 开关 | 亮度渐变 | 律动角色 |
|---|---|---|---|---|
| 阳台灯 linp.switch.t2dbw1 (<DID>) | 阳台 | 瞬开瞬灭 | 无 | 咔/强拍硬闪 |
| 客厅灯 lemesh.light.wy02 (<DID>) | 客厅 | 缓 | 0-100 | 呼/呼吸渐变 |
| 餐厅灯 yeelink.light.ceil45 (<DID>) | 餐厅 | 缓 | 可调(反馈~0.3s) | 渐变副律动 |
| 晾衣架灯 airer.pro3 (<DID>) | 阳台 | 缓 | 0-100 | 渐变点缀 |
| 造型灯（非智能灯+智能开关） | 客厅 | 瞬（随开关） | 无 | 咔/强拍硬闪 |

造型灯控制开关：领普三键 <DID> 第3键（siid=4/piid=1），见下方 MIoT 结构。

领普 linp.switch.*、chuangmi.plug.* 插座控制的灯 = 瞬开瞬灭；lemesh.light.wy02、yeelink.*、airer.pro3 自带渐变 = 缓开缓灭。

## 对位律动组合（用户认可思路）

- 瞬闪灯 + 渐变灯：强拍硬闪"咔" + 弱拍渐变"呼" → 4/4 拍主副分明
- 双瞬闪灯：左右/远近交替 8 分音符 → 快速"哒哒哒哒"连续感
- 瞬闪 + 晾衣架渐变：3/4 华尔兹"蓬擦擦"感

## 参数与限制

- 云端单次调用延迟 110-180ms（miotspec/prop/set）→ 拍子 ≥0.5s 稳（BPM 80-140），16 分音符会糊
- 时长对比必须拉开：短音 0.66s / 长音 1.32s / 乐句停顿 1.2s 起步；均匀闪烁用户判定"没有律动"
- 多灯交替 = 循环串行调用，禁止并发（防限流+顺序错乱）
- 播放脚本 try/finally 兜底关灯
- 渐变灯的"缓"由固件渐变决定，云端只设目标值；节奏设计按灯实际渐变时长匹配

## 可用灯具 DID 速查（云端在线，复核过）

- **瞬（领普开关控）**：阳台灯 <DID>、走廊灯 <DID>、餐厅灯 <DID>、次卧灯 <DID> / <DID>、厨房灯 <DID>、卫生间灯 <DID>、卧室灯 <DID>、客卫灯 <DID>
- **缓（自带渐变）**：客厅灯 <DID>、卧室灯 <DID>、次卧灯 <DID>、书房灯 <DID>（lemesh.light.wy02）；餐厅灯 <DID>（yeelink.light.ceil45）；晾衣架灯 <DID>
- 建议默认组合：客厅灯（缓）+ 阳台灯（瞬）+ 餐厅灯（缓）——一缓一瞬对位最强

## 一句话触发（用户要"说一句口令就自动跑、方便录视频"）

硬前提（已复核两次，别再试）：云端**不能**让小爱播歌（user ack timeout）、**不能**列出/建/触发米家场景（404 / 空 result）→ 没有任何"云端一句话"方案，App 里那一次配置只能用户手动做。

### 路径 D —— 当前选定方案：触发设备当事件源（推荐）

把"用户对小爱说的一句话"变成助手能读到的**设备状态变化**：

1. **用户 App 配一次**：小爱音箱 App「训练」或米家「智能 → 手动场景」，口令（如"开演"）→ 动作①播放指定音乐 ②**打开一个触发插座**。米家场景动作里若找不到"播放音乐"，就退回用户自己对小爱说"播放《X》"
2. **助手侧**：待命脚本轮询触发插座（云端 prop/get，1-2 秒一次），检测到 ON → 启动 `light_show_apt.py` → 结束恢复灯并把插座关回去；**脚本启动时若插座已是 ON：只复位成 OFF，不开演**（ON 只代表上次残留，立即触发会在用户没准备时突然闪灯）
3. **对拍标定**：音乐从收到指令到出声实测 **5-7 秒**（音箱搜索+缓冲，助手无法预知，浮动 ±1-2s）→ 跑 `/opt/data/scripts/calibrate_sync.py --media <带声视频>` 求差，把偏移写进 `--show-delay`（当前标定值 **5.0s**，实测残余偏差 +0.07s）

触发设备选型要求：**可读可写、不接关键负载**。候选：阳台电蚊香液 `lumi.plug.v1`（did `lumi.158d000268d62c`，siid2 piid1 = 电源，实测可读）。插座被误触最多是电蚊香通电，安全。

### 路径 A —— 备选：用户给助手一句口令

用户对音箱说"播放《X》"，同时对助手发一句固定口令（飞书语音"开演"也行）→ 助手立即跑 `light_show.py`。适合当天要出片、不想先配 App 的情况。

### 路径 C —— 长期：本地化

NAS 部署 HA + 小米官方集成（本地中枢，延迟 <100ms），音乐与灯全本地联动；代价 1-2 天部署（见 `references/home-assistant-migration-plan.md`）。

不要走：米家场景内的灯动作是固定延时开关序列，**做不到跟拍**，只适合简单闪。

## 网络与观感校准（2026-09-21 实测）

- **内网 192.168.31.x 不可达的根因 = NAS 异地部署**（不是 Docker 桥接；实测连 <LAN_IP> 路由器与 <LAN_IP> 摄像头均超时）。→ 改 host 网络/macvlan **无效**；一切**本地直连**路线（miIO 局域网协议、xiaomusic 推流、摄像头 RTSP）在现部署下都走不通，只能走米家云 API。要本地化只能在**家里**放常开设备（旧手机/平板/树莓派）再与 NAS 组隧道
- `/home/device_list` 响应里每个设备带 **`token` 和 `localip`**（音箱 Ultra = <LAN_IP>）——本地方案的 token 从这里取；**属凭据，不要写进对话或文档**
- **看不到灯的实际明灭曲线**（`siid2 piid2` 亮度是目标值，渐变过程不变；摄像头 `chuangmi.camera.061a01` 拿不到视频流）→ 观感校准走：**用户手机固定机位录一段 → ffmpeg 抽帧 + 算"饱和像素占比"**（每帧 ≥235 的像素比例；**不要用画面平均亮度**，手机自动曝光会把它抹平），据此得出实际渐变时长与"到全灭"的时刻。容器内已有 ffmpeg 7.1.5
- 用户已选参数：口令「**开始表演**」；**客厅灯演出时用「立即模式」**（录像逐帧实测：渐变模式下 1 秒级切换 = 连续 9.45 秒看起来常亮，2 秒级切换也只剩 0.3 秒暗窗口，跟不了拍；渐变只留给 ≥4 秒周期的慢呼吸）；歌曲《APT.》（BPM 用 `detect_bpm.py` 实测，不凭记忆报数）；触发插座用阳台电蚊香液（用户已同意）

### 视频亮度曲线分析（唯一能"看到"灯实际状态的办法）

1. 让用户手机**固定机位**录：画面里含目标灯，四段之间停 1-2 秒，录时口述"第几段"更好切
2. 跑 `scripts/analyze_light_video.py --video <file> --fps 10`（运行副本 `/opt/data/scripts/analyze_light_video.py`）
3. 原理（也是没装图像库时的通用做法）：ffmpeg 把视频降采样成 32x18 灰度 rawvideo → 切 4x3 网格，取**亮度方差最大**的格子当"灯所在区域" → 输出逐帧亮度曲线与每次亮起持续时长。**两个 venv 都没有 PIL/numpy，别走 numpy 路线**，`-f rawvideo -pix_fmt gray` + stdlib 足够
4. 判读：把"亮起→回到低亮度"的耗时与设定的渐变时长对比，偏差大就改 `--gradient`/拍子下限；曲线里若看不到明显起伏 = 灯根本没变化（先查设备在线与 siid 是否正确）

## 设备认领注意

米家 App 手动添加的非智能设备（如用户的"造型灯"=非智能灯+智能开关）**不出现在云端 device_list**（全量 81 台搜名字无果，virtualModels 也不含）。律动选灯时先向用户确认控制它的开关身份（墙壁开关/无线开关/插座），不要反复全量拉列表找名字。

## 开关类设备 MIoT 结构（2026-09-05 实测）

- 领普三键开关 linp.switch.t2dbw3：键1/2/3 = siid 2/3/4，piid=1 电源（用户"造型灯"=三键第3键 → siid=4 piid=1）
- 领普单键/双键 t2dbw1/t2dbw2 同理，从 siid=2 起逐键递增
- 晾衣架灯 airer.pro3 灯服务在 siid=3（piid1=电源/piid2=亮度），siid=2 探测全无效——多键/多服务设备控制前先 prop/get 探测，别假设键在 siid=2

## 演出工程规范（停止 / 快照 / 同步标定）

用户对自动化的硬要求：**能一句话立刻停 + 恢复成开演前的样子**。三件套（SKILL.md 有摘要，这里给实现细节）：

| 机制 | 文件 | 关键点 |
|---|---|---|
| 状态快照 | `/opt/data/cache/light_show_state.json` | 开演前写：三灯 did/siid/piid/值 + 客厅灯渐变设置；停止时按它还原（用户开演前可能就有一盏亮着） |
| 停止标志 | `/opt/data/cache/light_show.stop` | 工作线程每个事件前 `os.path.exists` 检查，0.2s 内停；**不要用 pkill 当停止手段**（SIGTERM 默认不走 finally → 灯卡住） |
| 停止脚本 | `/opt/data/scripts/light_show_stop.py` | 下标志 → 等收尾 ≤3s → 仍在跑就 SIGTERM → **再按快照强制恢复** → 回读复核打印 |

写设备一律要重试：`/miotspec/prop/set` 的**属性级 `result[0].code`** 才是真实结果，外层 `code:0` 不代表生效；linp.switch.* 首次写入常返回属性级 1 → 检查 + 重试一次（0.15-0.2s 间隔）。

### BPM 与首拍实测（换歌/换版本必做）

`/opt/data/scripts/detect_bpm.py --media <录音|带声视频>`：ffmpeg 转 8k 单声道 wav → 10ms 窗 RMS 包络取正差分得 onset → 自相关初筛（0.5 BPM 步长）→ **小数 lag 线性插值**精扫 → 再用"拍点位置对拍号做线性回归"精修斜率。纯 stdlib（无需 numpy）。

- 实测精度：合成 149 BPM 点击轨 → 自相关 150.00、**峰值精修 149.00 BPM / 首拍 0.00s**（自相关单独用会有 0.7% 误差，长片会累积漂移，必须用精修值）
- 换版本（原版 / DJ 版 / 加速版）BPM 会变：**以用户实际播放的文件为准**，让用户录 15-30 秒发来测
- 首拍偏移 + 音箱启动延迟 = 写进 `light_show_apt.py --delay` 的总偏移；再让用户录一段**带声音的视频**（画面含灯），同时跑 `analyze_light_video.py`（灯）与 `detect_bpm.py`（音乐）求差，可把偏移精确到 0.1s
- 灯的时间轴设计：按实测 BPM 生成；**同一盏灯相邻两条指令必须 ≥0.25s**（云端往返 110-350ms；8 分音符方案实测丢 44% 事件）→ 现行 v3 编舞：客厅灯每 2 拍闪（亮 1 拍）、阳台灯第 1/3 拍、造型灯第 2/4 拍左右交替
- **固定补偿的天花板**：音箱启动延迟浮动 ±1-2s，换歌/换时段都要重标定；想永久免标定只能让音乐与灯同一时间轴出发（需家里有常开设备推流，异地 NAS 做不到）
- **标定脚本** `/opt/data/scripts/calibrate_sync.py --media <带声视频>`：输出①灯第一次亮（去趋势亮度 ≥0.35×max）②音乐出现（低频包络节奏分 ≥0.40 且低频均值 ≥0.05，持续 ≥3s）③首拍（0.35s 合并双峰的鼓点峰）→ 直接给"该把 --show-delay 加/减多少"。判据别用整体音量（人声会骗）也别用饱和像素（自动曝光会压）
